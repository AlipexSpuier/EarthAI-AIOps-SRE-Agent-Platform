# 可靠性改进与实测口径

## 基线与目标

旧正式记录19次任务中10次回复完成、9次失败：8次空响应、1次HTTP500。已记录的SSH命令执行成功，失败主要在模型后续回复；回复完成不能等于目标命令已执行。

用户授权使用配置好的付费模型和服务器。本轮仅执行 `server_info` 与 `uptime`，不创建/删除远端文件，不重启服务、不修改Kubernetes资源，不读取凭据或业务内容。付费请求有限，记录安全元数据，源码包不含APIKey/服务器密码。

不能承诺任意模型/网络/服务器下数学意义的零失败，也不能靠把错误改成成功来达到数字。验收以“实际只读命令退出码0，模型根据真实结果完成回复”为准。

## 借鉴的做法

官方Cline和Roo Code源码核对见 `AGENT-RESEARCH.md`。引入分类有限重试、完整参数校验和错误反馈、上下文结果配对、重复错误熔断与不重放写操作。没有照搬无上限重试。

## 改动

- 模型HTTP408/429/500/502/503/504和暂时连接/读取故障有限重试；指数退避、随机抖动、Retry-After，所有恢复共享4次HTTP预算。
- 空响应、格式修复、流式降级使用同一预算；取消与401/403不盲重试。已公开片段若当前模型请求重试会reset，不拼接两次。
- 工具调用完整JSON与schema验证；常见资源别名、数字字符串做无歧义规范化，未知工具和缺字段反馈给模型改正，不把整个agent立即结束。
- 按目标连接只提供能用的工具，避免SSH和Kubernetes工具混用；模型必须取得工具证据，不能只写计划冒充实际检查。
- 原生网关不可靠时使用显式JSON控制协议：完整顶层tool/final对象，普通自然语言/命令示例不执行。宿主执行器与计划生成职责明确区分。所有参数和审批仍走同一后端。
- 验证成功的工具协议按供应商/模型/用户保存，下次直接用已验证协议，避免重复尝试已知不兼容的桥接路径。
- 成功写操作结果复用；不确定写操作不得自动重复。相同失败工具和规范参数累计两次后阻止无进展重复。reason文字变化不会绕过识别。
- 输出压缩保持有效JSON，不再把大JSON直接截成半截；上下文截取保留完整工具调用/结果配对。

## 配置持久化

六项配置（服务器、供应商、模型、智能体、项目、控制等级）存账号数据库。每次手动选择即按顺序保存，新会话、刷新、重新登录从服务器恢复。读取历史会话不反向覆盖默认配置。主题资料与聊天偏好用事务读最新数据合并，避免互相覆盖。

已删除/停用资源会清除而不偷偷换成其他服务器或提高控制等级。缺省字段沿用偏好，显式null表示清空。没有把草稿和凭据写进偏好。

## 退出与关闭浏览器

现有后端任务独立于浏览器，不需要重做。新增浏览器验收确认：退出登录仅删除当前session，不取消任务；关闭并重建浏览器后，重新登录可以恢复任务进度、事件和结果。相关 `persistence-verification.json`。

后端执行器进程重启仍不会自动重放未知写操作，原任务标记中断；这是与关闭浏览器不同的故障边界。

## 实测文件

- `live-baseline.json`：初次原生协议有限基线，3个模型各1次，未取得完整目标执行闭环。
- `live-enhanced.json`：仅增加重试与原生tool_choice不足以解决网关忽略调用的问题。
- `live-json-protocol.json`：明确兼容协议使Gemini与Claude各2次闭环通过，GPT仍误认为自己没有工具。
- `live-final-validated.json`：最终协议双样本，真实数字保留，不筛掉失败项。
- `live-engine-validation.json`：实际完整EarthAI引擎验收记录，包括未完成/测试超时。

原始记录是有限样本，任务简单、时间相近，不等于生产SLA或对任意任务的成功保证。
