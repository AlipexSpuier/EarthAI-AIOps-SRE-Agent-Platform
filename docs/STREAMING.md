# EarthAI 实时输出与执行轨迹更新

## 问题原因

原版本虽然通过 SSE 推送任务事件，但请求模型时使用 `stream:false`，只有整段回复完成后才发送给页面。工具参数和结果又默认折叠，并且界面把消息与工具分组展示，无法直观看出实际发生顺序。

历史记录中的三次“空内容”失败均发生在第一轮，只有通用报错、没有响应结束原因或工具事件。同一模型也有成功记录，因此不能据此判断该模型不支持工具调用，已有记录也不足以追溯确定供应商侧原因。

## 已实现

- 模型请求改为真正的 `stream:true`，接收 UTF-8 / SSE 分片，正文生成时立即推送 `assistant_delta`，不是事后打字动画。
- 支持文本内容块、现代工具调用分片、旧式 `function_call`；合法工具调用没有正文也是正常响应。
- 拒答、过滤、输出长度限制、参数残缺、网络中断、无正文及仅推理字段分别诊断。不将模型私有推理当作最终回答展示。
- 真正空响应只重试同一模型请求一次，不从头重跑任务，也不重复执行之前的工具。
- 仅当服务明确拒绝 stream 参数时，回退一次非流式请求并告知用户。如果服务忽略流式参数、直接返回 JSON，也明确标记实际非逐字返回，不伪造流式。
- 流中断或工具参数不完整时不执行半截工具调用；保留已收到的公开回复并标明中断。
- 执行记录按实际发生顺序显示公开回复、行动计划、每项工具操作、审批及结果。计划只是意图，不自动打完成勾。
- 工具步骤默认显示目标、目的、风险、准确 SSH 命令或 Kubernetes 操作/资源/命名空间、参数、退出码和耗时。
- `tool_start`、等待审批与 `tool_execution` 分开，未获授权的步骤不会被显示成已执行。
- SSH 实时读取 stdout/stderr，Kubernetes 显示真实 API 请求与返回进度，结果持久化。不是模拟终端输出。
- 切页、重连及刷新从持久化事件恢复；同一消息的流式片段由终稿替换，不重复显示。
- 大量流事件的历史恢复不再只读取前 1000 条。
- 供应商 `/models` 测试明确只证明目录接口可达，不再暗示已经验证聊天或工具调用；聊天测试不把空回复当成功。

## 安全与兼容边界

只发送公开文本，不暴露私有思维链。错误元数据仅保存白名单字段、结束原因、内容长度、工具数及数值 token 用量，不保存原始响应或推理正文。流式片段在发布前处理已知凭据和常见 token 表达式的跨片段脱敏；这不能保证识别任意业务日志中的所有机密。

API 仍要求 OpenAI Chat Completions 兼容格式，不能把 Gemini 原生或 Responses 端点直接当作该协议。实际逐字速度也受供应商是否缓冲响应影响。JSON 或明确不支持 SSE 的上游只能整段返回，页面会说明原因。

## 验证

使用隔离 SQLite、本机真实 HTTP SSE 测试服务和真实无头 Chromium，不调用用户付费模型，不操作生产服务器。

- 公开正文在模型结束前已出现在浏览器，第一批事件中尚无终稿。
- 四轮模型交互、三项工具执行，切至概览后仍完成。
- 工具参数和结果默认可见，刷新后终稿不重复。
- 空响应受控恢复后工具不重复执行。
- `content:null` 且只返回工具调用的多步执行完成。
- 中断流不会执行已收到但不完整/未结束的工具调用。
- 后端自动化 207 项通过，前端 38 项通过（包含流事件聚合和仅工具调用轮次）；TypeScript、Ruff 和生产构建通过。
- 360px 手机执行记录无横向溢出。
- 真实 SSH 协议测试验证 stdout/stderr 增量事件；审批前无真实 dispatch，允许后才执行；只读拒绝产生 blocked 结果。
