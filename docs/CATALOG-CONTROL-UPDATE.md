## 多选关联与技能注入

管理员和用户的智能体、项目表单均覆盖知识库与技能 `MultiSelect`，支持全选、清空及原生 form 提交。全选/清空只改变当前组 enabled 选项，不跨组、不改 disabled 项。

项目新增 `skill_ids:string[]`，不仅是界面保存字段：引擎先按智能体技能列表、项目技能列表顺序合并 ID 并保序去重，再取前 12 个槽位，仅注入其中存在且 enabled 的技能，不从后续列表补足。全选关联不改变此上下文上限，也不意味着全部绑定项都进入某次任务。调用统计仅记录实际注入的技能，并按同任务同资源去重。

## 精确控制等级授权

`allowed_control_levels` 是 `observe`、`approve`、`autonomous` 的非空精确子集，模式之间不隐含包含关系；拥有 autonomous 不自动拥有 approve 或 observe。

- 公开注册及管理员新建账号未指定授权时默认 `["observe"]`。旧账号完全缺字段时兼容原三种，不能擅自降为 observe；字段存在但为空、格式坏或含非法值时 fail closed，不回退为全授权。
- profile 的 `control_level` 只是偏好，不是授权来源。普通用户不能修改 grants；服务端同时约束资料/偏好中的模式选择，不能靠提交字段自行授权。
- 管理员单独编辑替换完整授权集合；批量界面只有勾选“应用控制等级授权”才提交替换，未勾选保留原值。空或非法集合使整批拒绝，不部分保存。
- 未授权模式、带未授权模式的 local agents/schedules 及相应关联选项灰显并禁止执行，但保留浏览、历史查看和编辑降级能力，不封禁整个 observe 模块。服务器/告警诊断固定 observe，仍必须有 observe 授权。

### 服务端执行边界与撤权

profile/preferences、资源 create/PATCH/import、conversation create/PATCH/messages 以及关联智能体均需校验授权。任务模式和本地智能体自身模式都必须在授予集合中，observe 会话或定时任务不能包裹未获授权的 approve 智能体绕过校验。

引擎创建任务、每轮模型调用、工具执行与审批前后，以及调度器实际派发和立即执行，均复查最新账号/grants 与关联智能体状态，不信任前端灰显、旧会话或启动时快照。

收紧授权时先持久化新集合，再仅取消任务模式或关联智能体模式被撤权的活动任务，并使这些任务的待审批项过期；仍获授权的任务不因集合变化全部取消。取消不能撤销已经发往远端的动作，仍需核查实际状态。

## 用户八类 JSON 导入

`POST /api/{kind}/import`，`kind` 仅为 `agents`、`skills`、`knowledge`、`projects`、`servers`、`providers`、`schedules`、`alerts`。请求体 `{items:[...]}`，每批 1–200 个对象。

- 先全量校验，再同一事务创建全部资源并写入审计；任一项非法则整批不落库。只新增当前 owner 的 private 资源，不覆盖、不接受客户端 ID，不支持批内交叉引用；关联只能指向现存 owner 资源或其默认副本，不能使用模板 ID 或他人 ID。
- 导入沿用正常创建的字段、权限、密钥和控制等级校验。定时任务 `enabled` 默认 false，后续启用、立即执行与调度仍受相同授权约束。
- 供应商提交后仅进行一次模型目录发现；失败返回 warnings，明确配置已保存、可重试目录同步，不能误导用户重导。密钥密封保存，不在响应、warnings 或审计中输出明文。
- conversations、个人 files 和知识 documents 不在 JSON 导入范围。knowledge 只导入知识库元数据，文档仍走现有 multipart 上传，不由元数据导入生成正文或索引。

## 启动、schema 与原数据

既有初始化可用 `CREATE TABLE IF NOT EXISTS` 和索引初始化补建缺失表/索引，但不会修改已存在表的列，也不是完善的通用 `ALTER` 迁移框架，不能保证未来只改 CREATE 定义即可升级旧库。

本轮无需新增列：授权使用 `users.data` JSON 新 key，项目 `skill_ids` 使用 `entities` JSON，目录沿用既有表。保留其他 JSON keys、旧数据、既有密文及原主钥，不清库、不重置 usage 起点。每次容器 startup 执行幂等 init；目录内容、首次随机结果和 marker 仅随同一成功事务提交，失败不写成功标记。

一次性 `control_grants_v1` 数据迁移为缺字段旧账号补齐原三种授权，不覆盖新账号或管理员已显式配置的集合，已有坏字段仍 fail closed。手工构造仅五表的旧库经完整 TestClient startup 补齐所需表/索引，旧密码哈希、原主钥、密文行及管理员修订/删除保留，重启前后完整快照不变。本轮已处理缺失表/索引初始化、JSON 授权/项目技能数据和目录事务 marker；这些验证不代表未来任意列变更都能自动迁移。

部署约束不变：唯一 `compose.yaml`，服务/顶层均无 `volumes`；平台将原 `10.53.10.5:/nas` 直接挂到容器 `/app/data`，不要求宿主 NAS 路径，不加本地 state、第二挂载、启动复制或异步写回。单 worker、单写容器、SQLite DELETE/FULL；原 `master.key` 或原环境主钥持续保留。Compose 本身不提供 NAS 持久化，平台每次重建须保留原挂载，DELETE/FULL 也不消除 NAS 锁与同步风险。步骤见 [USAGE-NAS-UPDATE.md](USAGE-NAS-UPDATE.md)。
