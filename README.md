## 本轮空间模块与团队空间（已验收）

- `User.space_modules?: ('personal'|'team')[]` 独立于角色与 `allowed_control_levels`，新账号默认 `["personal"]`，允许 `[]`。旧账号仅缺字段时由 `space_modules_v1` 补 personal，已有显式坏值拒绝授权；普通用户不能自授，管理员创建、编辑及勾选应用的批量修改可配置。
- 关闭 personal/team 只是隐藏入口并拒绝对应 API；既有 entities、个人文件及 blob、团队与成员关系保留，重新开放仍在。永久删除账号是另一操作：个人文件可清理，团队所有者必须先转交，包括已归档空间；删除或升管理员的整批请求先事务校验，冲突返回 409，不部分执行。
- 用户 `/team-spaces` 可创建自己的空间，只能访问所属团队；管理员 `/admin/team-spaces` 是独立全局治理入口，不是默认资源模板，也不授予运维执行权。viewer 只读；editor 可管理全部共享文件；manager 可改空间资料及管理 viewer/editor；owner 还可授权 manager、转交、归档/恢复，始终保护唯一所有者。文件删除需确认。
- 添加成员精确匹配已有邮箱/账号，不公开用户目录、不创建账号；只接收已启用且无需强制改密的普通账号。未开 team 且未被 `team_invites_blocked` 阻止时，可合并开启 team，保留 personal 及其他授权；管理员将已开启的 team 关闭会阻止邀请绕过，须重新勾选 team 才解锁。移除/离开不关闭 team，也不删其上传的共享文件。
- 删除团队空间是 `deleted_at` 软归档，保留文件；owner/admin 可恢复。归档只保留基本信息与成员只读，拒绝文件访问；所有操作者（含管理员）的转交、退出、成员写入与文件写入都须先恢复，不设救援例外。本轮不提供永久清理。所有者不能直接退出、降级或移除，须转交现有活跃普通成员；原所有者变 manager，平台阻止的目标须先由管理员开通 team。
- 个人文件 API 和 Agent `list_files/read_file/write_report` 使用最新 personal 授权，包括上传等待后、成功写结果缓存复用前复查；关闭后不创建、不读、不 unlink，原 ID/字节保留。本轮不新增团队 Agent 工具，不自动把共享文件送给模型，不允许跨团队读取。

启动幂等补建 `team_spaces/team_members/team_files` 及索引，空间授权存于 `users.data` JSON；不清用户库、不改原主钥。团队 blob 平铺在原 `/app/data/uploads/team-<uuid>`，现有备份平铺 glob 可收集，不增加持久盘或 NAS 挂载。schema/API 字段以 [teams.py](backend/teams.py) 和 [team_routes.py](backend/team_routes.py) 为准；自动化专项、浏览器及隔离容器重建的数据/原主钥保全检查均已通过，报告见 [交付记录](docs/DELIVERY.md)。

## 上一轮更新（已通过自动化与隔离浏览器验收）

- **默认目录只增补，不重置。** 保留 50 个知识库及每库原有 2 篇手册，首次升级为每库随机追加 1–10 篇有实际正文的运维专题；随机结果与迁移 marker 持久化，重启不重抽，不伪造历史记录或官方资料。标准未改目录的技能从 50 项增至 100 项，新增 50 项均为实质运维技能；管理员改动/删除及个人 `override` / `deleted` 均受保护，不为凑数量重建。新技能不自动改变既有智能体绑定，可由用户全选关联。500 篇是有正文的候选专题，不是全部落库；本次隔离浏览器实例初始为 100 技能、50 库、392 篇文档（每库 3–12 篇），392 不是固定值或用户生产数据。
- **全选是关联操作，不是上下文扩容。** 管理员及用户的智能体、项目表单中，知识库和技能多选支持全选/清空与原生表单提交；操作仅影响当前组可用项，不跨组、不改禁用项。项目新增 `skill_ids`；引擎先按智能体、项目顺序合并技能 ID 并保序去重，再取前 12 个槽位，仅注入其中存在且 enabled 的项，不从后续列表补足。全选关联不改变此上下文上限。
- **控制等级由管理员明确授权。** `allowed_control_levels` 是 `observe`、`approve`、`autonomous` 的非空精确子集，等级之间不隐含包含关系。公开注册与管理员新建账号默认仅 `observe`；旧账号缺字段兼容原三种，坏字段拒绝授权。资料中的 `control_level` 只是偏好，普通用户不能授予自己权限。未授权模式、关联本地智能体及定时任务灰显并禁执行，但可查看历史、浏览和编辑降级，不封禁所有只读模块；服务器/告警诊断固定要求 `observe` 授权。服务端入口、引擎、审批和调度均须读取最新授权；收紧时先保存授权，再只取消任务模式或关联智能体模式被撤权的活动任务并使其审批过期。已发出的远端动作不能撤销。
- **用户 JSON 导入是私有新增。** 八类资源 `agents`、`skills`、`knowledge`、`projects`、`servers`、`providers`、`schedules`、`alerts` 使用 `POST /api/{kind}/import`，`items` 为 1–200 个对象，先全量校验，再同事务新增和审计；不覆盖、不接受客户端 ID、不支持批内交叉引用，仅可引用现有 owner 资源/默认副本。供应商提交后仅做一次模型目录发现，失败返回警告而不是提示重导，密钥密封保存且不输出；定时任务导入默认关闭，仍受相同授权校验。会话、个人文件和知识文档不在此导入范围，知识导入只建元数据，文档仍走 multipart。

上一轮不新增数据库列：授权写入 `users.data` JSON 新 key，项目 `skill_ids` 写入 `entities` JSON，目录沿用既有表。每次容器启动执行幂等初始化，目录内容、随机结果与 marker 仅随成功事务提交；旧数据及其他 JSON keys、原密文和主钥保留。一次性 `control_grants_v1` 迁移为缺字段旧账号补齐三种授权，不覆盖新账号或管理员显式配置。手工五表旧库经完整 TestClient 启动补全所需表/索引，旧密码哈希、主钥、密文行及管理员改删保留，重启完整快照不变。此验收覆盖上一轮初始化和 JSON 数据迁移，不代表通用 `ALTER` 框架；`CREATE TABLE IF NOT EXISTS` 不会修改已有表列，不能保证未来只改 DDL 即自动升级。NAS 部署约束不变。

## 已实现

- 注册、登录、会话 Cookie、用户数据隔离、个人资料、头像和深浅主题。
- 新建和历史对话，选择智能体、项目、目标服务器、供应商、模型、控制等级。
- 后台 Agent：OpenAI-compatible tool calling、多步计划、工具调用、结果反馈、下一步推理、最终验证与报告。最多 24 轮，单次最多 12 个工具调用。
- SSE 实时执行流：请求模型真正开启流式，公开正文随分片输出；按时间顺序展示工具目标、参数、准确命令、实时 stdout/stderr、审批、结果与耗时。事件落库并支持重连恢复。前端运行上下文在路由外，切换页面不会取消任务；关闭浏览器也不会中止后端任务。
- 三种控制级别：只读观察、变更审批、自主执行。自主模式的高风险动作仍需审批；审批有效期 30 分钟；支持拒绝和停止任务。
- SSH 服务器：密码或未加密私钥认证、SHA256 主机指纹校验、真实远程命令、超时与退出码。在远端已有 kubectl 的情况下可管理远端集群。
- Kubernetes 集群：自包含 kubeconfig，校验 TLS，通过 API 查询节点/工作负载/事件/日志、Server-side Apply、扩缩容、滚动重启与删除。
- 个人空间：模块开启时可上传、下载、删除文件；Agent 读取文本/PDF、写报告也须通过最新 personal 授权。
- 团队空间：独立成员角色、共享文件、精确账号邀请、所有权转交与可恢复软归档；不自动向 Agent 提供团队文件。
- 知识库：上传 PDF / Markdown / UTF-8 文本 / JSON / YAML / 代码，分块索引，FTS5 关键词检索，中文子串匹配，检索结果作为 Agent 上下文。没有将关键词检索伪称为向量检索。
- 技能库与智能体：职责提示词、技能指令、知识库绑定，执行时真实注入模型上下文。
- 项目：绑定服务器、知识库与技能，项目技能真实进入受限模型上下文；项目会话不能执行不属于项目的已限定服务器。
- 模型供应商：保存 API Base URL + API Key + 模型列表，连接测试，模型切换。支持 OpenAI-compatible `/chat/completions` 工具调用；不直接支持 Anthropic 原生协议。
- 定时任务：五段 cron、IANA 时区、启停、立即运行、下次执行时间；由常驻调度器调用同一 Agent 引擎。重启后合并错过的周期，不大量补跑。
- 告警诊断：手动创建、任务失败自动告警、解决状态、只读 Agent 诊断入口。
- 概览：真实资源数量、任务活动、近期执行、告警和审计记录。没有虚构 CPU 曲线或假集群状态。

## 界面与入口约定

各模块从左侧主导航统一进入。「AI 对话」打开新会话，历史对话从页面右上角查看。个人资料、头像、主题、默认控制等级及退出登录统一在「偏好设置」。管理页创建操作仅保留页头入口，上传操作位于相应上传区域；带具体资源的诊断和执行记录可直接打开对应任务。

聊天框内的智能体、项目、服务器、供应商、模型与执行控制采用自定义选择浮层；输入、搜索、密码和选择器不再出现彩色焦点线框，保留原有阴影与普通按钮键盘提示，深浅主题一致。登录/注册保留一枚页面密码显示按钮并隐藏浏览器重复的原生显示按钮。供应商为独立控件，模型列表只显示该供应商的模型，切换供应商会重置为其默认模型，支持搜索与自定义模型名。输入区域与上下配置条采用独立网格行，聚焦和多行输入不与选择器重叠。长内容仅在主内容区正常滚动，聊天输入框保持可见。界面验收与截图见 `docs/UI-IMPROVEMENTS.md`。

### 本地与远程智能体、自定义排序

创建或编辑智能体时可选择「本地智能体」或「远程智能体」。本地使用现有模型、系统指令、技能和知识；远程只保存 HTTP(S) 网页链接，通过卡片在新窗口打开，不向对方发送本地会话或服务器凭据，也不能被会话/定时任务引擎当作本地执行器。用户每次通过卡片打开 default 或 private 远程智能体，单独 `POST /api/agents/{ownerAgentID}/open` 登记一次点击；不创建模型 run，不用 GET 登记。普通点击、键盘激活、Ctrl/Meta 点击及中键均登记，右键菜单直接打开、复制 URL 或直接访问外部站点不能追踪。登记失败显示错误 toast，不能伪报登记或外部打开成功。

用户智能体页「调整排序」支持拖拽及上移/下移，显式保存后按账号持久化；刷新、重新登录仍保持，个人 `agent_orders` 优先于平台排名。管理员的「调整排序」始终包含全部默认智能体，不受筛选或勾选影响，可拖拽、上下移动、保存或取消；保存全量 ID 后原子更新平台排名，没有个人排序的用户跟随，已有个人排序优先保留。数字排序输入及其表单 payload 移除，内部 `sort_order` 仍保留；仅改排名不改内容，也不因活动 run 阻止排序。新增智能体追加到末尾，普通内容编辑不改变位置；默认本地副本不能由用户转为远程，私有智能体转换规则不变。

系统概览底部「审计日志」可选最近24小时、7天、30天、全部时间或自定义本地起止时间，查询时转为 UTC，服务端按范围及账号筛选，最多100条。网站已提供 ICO、多尺寸 PNG、Apple Touch 图标和 web manifest。

## 流式输出与模型兼容

模型使用 `stream:true` 的 Chat Completions 请求，解析公开正文、完整工具分片、文本内容块与旧式 function_call。只返回工具调用而 `content:null` 属于正常响应；仅推理字段不作为最终正文。真正空响应最多重试一次当前模型请求，不从头重放工具。截断、拒答、过滤和无效格式分别报告，错误附安全结束元信息，不笼统断言模型不支持工具。

若供应商明确拒绝 stream 参数，会告知并改用一次同模型非流式请求；服务直接返回 JSON 也会说明未实际逐字推送，不伪造打字动画。实际生成速度取决于上游是否缓冲。操作轨迹是工具证据，不是模型私有思维链。详细说明与验收见 `docs/STREAMING.md`。

## 可靠性恢复与永久聊天配置

模型请求对408/429/指定5xx和临时传输故障进行指数退避与Retry-After重试，空响应、格式修复和降级共享4次HTTP预算，不盲重发已执行工具。工具参数按schema验证，错误会作为同调用ID结果反馈给模型改正；只提供当前连接可用工具。显式要求检查时必须取得工具证据，不把文字计划判成执行成功。

当前供应商存在原生工具桥接兼容问题时，已验证模型可使用显式JSON控制协议；只有完整顶层控制对象才解析，仍经过同样的参数、目标和审批校验。成功协议按用户/供应商/模型持久化。工具写操作失败或状态不确定不自动重发；同任务成功写结果可复用，连续无进展会停止。研究依据见 `docs/AGENT-RESEARCH.md`。

服务器、供应商、模型、智能体、项目与控制等级六项选择自动保存到账号数据库，新会话、刷新、重新登录恢复。历史会话读取不改默认；明确清空才清空。退出账号或关闭浏览器不取消后台任务，恢复登录可查看进度；后台执行器进程重启仍会标记中断而不冒险重放副作用。

此前的只读验收使用授权付费模型和已配置 SSH 主机执行 uptime，未对业务或集群进行写操作。历史实测仍有模型拒绝协议和上游延迟/超时，不能宣称已实现零失败；包含失败样本的结果见 `docs/LIVE-RESULTS.md`、`docs/RELIABILITY.md`，不代表上一轮综合验收结论。

## 管理员后台与默认资源权限

首次启动会幂等创建账号 `admin`、密码 `admin`，以 scrypt 哈希保存。首次登录必须先改为至少 8 位的新密码；重启和升级不会重置已改密码。登录框支持账号或邮箱，公开注册仍只创建普通用户，无法通过提交角色字段提权。请勿把初始密码长期保留或将管理员账号用于日常运维。

管理员侧栏包括系统概览、智能体管理、用户管理、团队空间管理、知识库管理、技能库管理、项目管理、服务器管理、模型供应商管理、定时任务管理、告警管理和界面管理。团队入口 `/admin/team-spaces` 独立于默认模板；管理员只治理平台，不运行普通用户聊天与诊断，前后端均校验角色。用户管理支持角色、停用、改名、密码重置、删除与批量处理；初始 admin、当前管理员及最后可用管理员受保护。停用、重置密码、提升管理员或删除用户会停止其活动任务并撤销相关会话；删除/升管理员还须先转交所有团队空间（包括归档），整批预检冲突 409，不部分执行。停用或关闭模块则保留空间所有权。

七类默认资源由管理员维护，新账号自动继承，未发生个人改动的副本继续跟随模板同步；每用户副本保持稳定 ID 并重映射依赖，保留既有会话与偏好引用。普通用户可编辑、删除自己的默认技能、知识库和本地智能体副本，知识文档可上传、删除；首次个人写入后整份内容归个人管理，不反写模板或其他用户，也不再跟随后续模板内容。`default_owner_states` 持久化 `override` / `deleted`：删除的同模板 ID 副本不会因同步或重启复活，新模板 ID 正常下发；模板删除或改为 remote 也保留已有个人 override 的 local 内容与类型。排序展示 metadata 仍跟随平台 rank，个人 `agent_orders` 优先。

默认 remote 智能体始终只读，其他默认 providers/servers/projects/schedules 仍只读；可按控制等级使用允许的能力，不能修改默认配置。用户不可把默认 local 副本改为 remote，避免改成只读后无法继续管理；私有资源原 CRUD 与类型转换规则不变。接口 `read_only` 由服务端按类型计算，不能只凭默认来源判断。默认服务器、供应商凭据不回显；发布它们代表允许所有普通用户使用相应连接或额度，务必最小权限。完整边界见 [个人资源更新说明](docs/PERSONAL-RESOURCES-UPDATE.md)。

资源管理支持全选、批改、批删及 JSON 批量新增；默认知识文档支持全文阅读/编辑与批删；供应商支持逐行模型增删改和批量替换模型目录。默认定时任务新建关闭，启用后每位普通用户都会调度，可能产生多次调用。管理员告警管理覆盖所有账户，状态变更直接反映到原用户。指南维护位于帮助页的集中管理入口，独立于默认资源模板，不向用户实体目录复制正文。

界面管理统一配置名称、副标题（原 WORKSPACE）、宣传语、系统图标、favicon，以及标题/副标题字体、字号、颜色；图标仅接收本地图片，字体不访问公网。右上问号跳转角色化帮助页，管理员11节、用户12节，每节使用独立的 `/help/:section` 地址并只显示该节正文；目录、上一节/下一节、搜索结果均跳转独立章节，支持刷新和前进后退。聊天正文使用安全 GFM Markdown 渲染，支持对齐表格、引用、任务列表、代码复制；不执行 HTML，也不自动加载远程图片。

平台维护的指南现存于 SQLite `help_guides`，管理员从自己的帮助页点击「管理使用指南」统一维护管理员/普通用户两套章节，可新增、编辑、删除、批量删除及预览。初始提供11/12节完整内容，仅首次初始化；管理员修订或删除后重启不会覆盖或复活。普通用户只能读取本角色指南，不能更改内容或读取管理员私有指南。两角色顶部均保留问号和可见「使用指南」文字入口，紧邻安全说明。

用户技能库与知识库采用受可用视口高度限制的双区工作台，目录和正文各自滚动，资源增加不会撑成长页面。手机上改为上方有限目录、下方独立正文，短屏仍可正常访问。知识库的「查找知识库名称或描述」位于本地索引说明旁，只筛选目录，不切换当前阅读库，也不清除库内全文检索结果。用户供应商卡片只为标题之后的只读徽标增加局部 10px 上间距，不修改全局徽标或其他卡片样式。

### 全资源调用统计与远程点击

管理员概览显示智能体、知识库、技能三张独立「总调用次数」卡，包含所有用户默认及 private 资源，以及已删除资源/模板的历史。`usage.scope='all_resources'`、`usage.method='per_run_resource_and_remote_click'`；默认管理卡的 `usage_count` 仍按模板来源汇总所有用户副本，和概览的范围不同，不能要求卡片之和等于全量总计。用户 agents/knowledge/skills 三类目录每项也返回当前 owner 单资源 `usage_count`。

本地智能体在首次发起模型请求时计数；技能先按智能体、项目顺序合并 ID 并保序去重，再取前 12 个槽位，仅统计其中存在、enabled 且实际注入模型上下文的资源，不从后续列表补足；知识库仅计算检索命中并进入任务参考的资源。`resource_usage` 仍以 `(run_id,kind,resource_id)` 去重，模型重试、多轮推理和同任务重复知识命中不重复计数。default/private 远程智能体每次链接激活成功 POST 则独立写入 `remote_agent_clicks`，不建模型 run；页面查看、手工知识搜索不算。点击只证明登记成功，不证明外站加载或站外任务成功，也不是供应商请求数、token 或账单。

删除资源/模板不抹掉概览历史；删除用户仍清理其全部 usage/click rows，因此总计可以下降。原 `usage_started_at`（接口 `started_at`）不变，不推算历史任务或回填旧远程点击。启动幂等补建缺失表/索引，不自动修改已有表列，不清已有 usage 数据，不覆盖原 `master.key` 或环境主钥；上一轮 JSON 新 key 及目录 marker 边界见顶部契约。详细口径见 [调用统计与 NAS 更新说明](docs/USAGE-NAS-UPDATE.md)。

## Docker 部署

唯一部署文件为 `compose.yaml`，应用环境为 `EARTHAI_DATA_DIR=/app/data`、`EARTHAI_SQLITE_JOURNAL_MODE=DELETE`，不设 STATE/UPLOADS 覆盖；服务和顶层均无 `volumes` 定义。部署平台直接将 `10.53.10.5:/nas` 挂到容器 `/app/data`，这是唯一外部持久化挂载，无需填写宿主机 NAS 路径或 NAS 路径变量，也不增加其他挂载。

**Compose 本身没有持久化定义。** 单独执行 `docker compose up` 不会获得这份 NAS 持久化；只有平台在最终部署配置中保留 NAS → `/app/data` 挂载，数据才持久。平台导入 Compose 后若重建容器，也必须继续保留该存储设置；目录存在或健康检查成功都不能证明挂载正确。

平台更新流程：

1. 暂停定时任务、上传和其他写入，等待或取消活动任务，核查远端已执行操作；用平台停止全部旧写入实例，备份原 NAS 数据及原主钥。保留实际项目/服务标识、origin、Cookie、注册策略与受保护环境配置，不执行 `down -v`。
2. 导入唯一 `compose.yaml`，在平台最终部署配置中保留原 `10.53.10.5:/nas` → `/app/data` 挂载，确认 DATA、DELETE、单 worker、原镜像和访问设置。本用户已使用原 NAS 直挂，不搬数据，不做 split、本地 state 或启动复制。
3. 通过平台启动后检查实际挂载及原数据，再验证原账号、凭据解密、会话/统计、文件和品牌；健康检查只是其中一项。完整步骤见 [单 NAS 更新说明](docs/USAGE-NAS-UPDATE.md)。上一轮未部署用户实际服务。

可先做静态配置校验，不打印可能含密钥的展开配置：

```bash
docker compose -f compose.yaml config --quiet
```

该命令只校验 Compose 配置，不验证平台 NAS 挂载、数据保留或运行状态。若需查看完整 `config` 输出，只能在受控终端核对，不对外分享可能包含主钥的内容。实际挂载与运行检查依赖平台最终配置和原数据。

镜像标签继续使用 `earthai:latest`，本轮已构建并通过扩展无网络容器持久化检查，本地镜像 ID 与报告见 [交付记录](docs/DELIVERY.md#镜像与源码包最终项)。不同 `docker run --rm` 容器复用同一临时 bind → `/app/data`，原主钥、个人/共享文件 ID 与字节、成员、模块和归档状态保留；未使用真实 NAS 或用户 volume。本次最终容器样本随机初始化为 367 篇文档，不是固定规模；浏览器验收也已通过。源码交付位置为 `/home/god-agent/god-agent-workspace/EarthAI-source.zip`，包含源码、前端构建、唯一 Compose 与交付文档，排除账号数据、上传文件、主钥、备份和私有配置。平台更新保留原 NAS 挂载与主钥，不清库；回退使用原容器确切镜像 ID，不重新打旧镜像标签。

应用监听与 Compose 映射均绑定 `0.0.0.0:8000`，可从可达局域网访问；systemd 与 Nginx 示例也显式监听 `0.0.0.0`。健康检查、反向代理上游等回环目标仍使用 `127.0.0.1`，它们是连接目标，不是监听绑定。不要把运维平台直接暴露到公网。

按部署要求，运行时镜像只保留 root 账号/组，应用使用 `USER root`，Compose 指定 `user: "0:0"`；未创建 earthai 用户。原配置没有 `privileged` 字段，因此未额外添加，Docker 默认仍为非特权容器；保留 `no-new-privileges`，先丢弃 capabilities，再仅补回 `DAC_OVERRIDE` 与 `FOWNER` 以兼容旧版非 root 数据卷的读取和权限维护，不挂载宿主 Docker socket 或 kubeconfig。root 运行不等于特权容器，但相对非 root 会增大风险，请限制访问和挂载。

旧默认命名卷 `earthai-data` 已不再是当前 Compose 默认配置。其他用户若历史数据仍在命名卷，不能直接以新配置启动并丢弃原挂载；应先用旧配置保留原卷，停写备份并确认迁移完成后再切换，不能执行 `down -v`。本用户原数据就在 NAS，不需要从命名卷迁移。

### 单 NAS 直接持久化

数据库、原磁盘 `master.key`、`branding/`、`uploads/` 全部在平台挂载的 `/app/data` 直接读写，不使用本地持久盘、启动复制或周期异步写回；内存缓存不是唯一数据源。

`backend/store.py` 保留 WAL 兼容能力，当前 `compose.yaml` 显式使用 DELETE，每个物理连接均设置 `synchronous=FULL`，禁止 OFF/MEMORY 等不安全日志模式，不关闭 fsync 或持久化同步。SQLite 官方说明 [WAL 不适用于网络文件系统](https://sqlite.org/wal.html)，并提示[网络锁和同步可靠性风险](https://sqlite.org/useovernet.html)。DELETE 是缓解措施，不是 NAS 安全认证，不能保证任何故障下零丢失；远程 FULL 提交仍可能很慢，不承诺更快。

旧 WAL 库必须先停所有旧实例，再由 SQLite 在新实例启动时切换 DELETE；不能手动删除 `-wal` / `-shm` / `-journal` 或裸复制运行中的数据库。只运行一个 worker、一个写同目录容器。同一 NAS 目录和原主钥重新挂回后可读取已提交记录；执行中任务中断不自动重放，恢复仍受 NAS 锁、同步与损坏风险约束。

旧 split 路径 API 与 `scripts/migrate_nas_state.py` 仅兼容旧配置，本次不执行迁移。本用户未做 split；若其他部署已做 split，须先确认有效数据库及密钥位置，不能丢弃旧 split 库、直接启动 NAS 中的旧副本。完整停机更新与同 NAS 备份见 [调用统计与 NAS 更新说明](docs/USAGE-NAS-UPDATE.md)，不要用旧升级脚本的历史挂载配置替换本方案。

上轮独占借用连接池、知识列表 `GROUP BY`、不变默认目录检查仅 3 条 SELECT 且无 DML、偏好/排序稳态 GET、前端在途 GET 合并（无 TTL 结果缓存）、SSE 通知/十秒心跳与 cron SQL 筛选优化全部保留。[历史隔离报告](docs/nas-performance-verification.json) 为此前 WAL 环境：50 库/100 文档、每条 SELECT 人工延时 5ms，等价旧逐项路径对比当时接口为查询/连接借用 52→3，中位数 287.16→20.11ms；20 次顺序读仅创建 1 个物理连接。这不是 DELETE/NAS 实测或通用加速保证；「3 条 SELECT」不是整个启动过程。更早的 582 后端/71 前端测试为历史记录；上一轮单 NAS 调整的 WAL/DELETE 两种模式分别通过 603 项，包含 21 项单目录/日志恢复专项，及临时目录的隔离容器删除重建检查也仅为历史证据。进程异常退出不等于 NAS 物理断电测试，不能验证上一轮平台挂载。未部署用户实际服务或测量真实 NAS，详细边界见 [DELIVERY.md](docs/DELIVERY.md)。

`deploy/nginx.conf` 给出了 SSE 反代配置。正式环境请启用 HTTPS，把 `EARTHAI_COOKIE_SECURE=true`，并将 `EARTHAI_ALLOWED_ORIGINS` 设置为真实 HTTPS 域名（完整 origin）。生产部署仅运行一个后端 worker；进程内通知不跨 worker，不要横向扩容同一个 SQLite 数据目录。

如果使用系统服务，参考 `deploy/earthai.service`；按示例准备 `/opt/earthai`、Python 虚拟环境和 `earthai` 专用用户后再安装此单元文件。`.env` 可由 Uvicorn 的 `--env-file .env` 或 systemd 的 `EnvironmentFile` 加载。

## 首次接入

1. 先以 `admin / admin` 登录并改密，配置平台默认资源或创建普通用户；日常运维切换普通账号，也可按注册开关自行注册。
2. 在「模型供应商」填入名称、Base URL 与 API Key 即可，模型列表和默认模型均可留空。保存后会请求一次 `/models`，成功时取返回的首个可用模型作为默认；失败或空目录保留供应商配置并明确提示，可重试同步或手填。编辑保存不自动请求，手动同步保留仍有效的默认模型。Base URL 包含版本前缀，例如 `https://api.openai.com/v1`，不要填写 `/chat/completions` 完整路径。若私有服务不校验密钥，可填 `local`。模型目录可达不等于已验证工具调用能力。
3. 在「服务器」添加 SSH 主机或 Kubernetes 集群，测试连接。
4. 创建对话，选择服务器和模型，先用「只读观察」执行一次健康检查。
5. 需要重启、扩缩容或配置变更时，选择「变更审批」，逐项检查实际命令/资源对象后再批准。

### SSH

连接需要从 EarthAI 后端可达的 IP/域名和端口。新连接默认「首次连接自动信任并保存指纹」，无需手工填指纹；第一次 SSH 握手收到的主机指纹会在认证前原子保存，之后只能匹配已记录的指纹，指纹变化会拒绝连接，绝不自动覆盖。你也可关闭首次自动信任，并预填经过独立核实的 SHA256 指纹。

首次信任（TOFU）只固定第一次看到的主机，不能独立证明第一次连接没有中间人；请确保地址及网络可信。更换主机地址或端口后旧指纹会清除，需要重新记录或核实。此机制不会关闭 Kubernetes TLS 校验。

建议使用受限的专用 SRE 用户、禁用 root 登录；为该账号配置受限 Kubernetes RBAC。SSH 工具会在目标主机的 shell 中执行命令，不会把 EarthAI 自身的文件系统当作远端环境。

### Kubernetes

支持 ServiceAccount token 或内嵌客户端证书/私钥，必须使用 HTTPS。kubeconfig 需提供正确的 `current-context`；私有 CA 需嵌入 `certificate-authority-data`。

出于安全原因，不支持 kubeconfig 的 `exec` 插件、外部凭据文件、外部 CA 文件和 `insecure-skip-tls-verify`。将已有 kubeconfig 展开为自包含配置，或使用短期专用 ServiceAccount token。令牌到期后需要更新服务器凭据。

`deploy/kubernetes-observer.yaml` 是最小只读 RBAC 起点，不包含 Secret 读取权限。需要真实写操作时，请根据命名空间和资源额外授予最小权限，不要直接分配 `cluster-admin`。网络不可达的集群需要 VPN、内网路由或通过可达的 SSH 主机接入；平台不能绕过网络隔离。

## 安全边界

- 密码使用带随机盐的 scrypt；会话令牌仅在 Cookie 中返回，数据库仅保存会话令牌哈希。
- 模型密钥、SSH 密码/私钥与 kubeconfig 使用 Fernet 加密。单 NAS 部署保留 `/app/data/master.key`（权限 0600）或优先级更高的原 `EARTHAI_MASTER_KEY`；不能生成替代密钥。环境主钥不会归档，须另行安全保管并在每次重建持续提供原值。
- 必须一并备份数据库、上传文件和主密钥。密钥丢失后原凭据无法解密；仅凭数据库备份无法恢复连接。
- API 不返回保存的密钥。更新时留空表示保留原值。事件与工具输出进行常见凭据脱敏，但不能保证从任意业务日志中识别所有机密。
- 所有资源和审批按登录用户授权隔离。页面不执行模型输出的 HTML；接口有同源写入检查、Cookie SameSite 和登录限流。
- 只读 SSH 命令采用保守白名单，`kubectl` 只接受限定的安全参数；含 shell 拼接或不认识的命令按高风险处理，即便自主模式也会要求审批。Kubernetes 写动作由服务端分类。规则不是通用 shell 沙箱；尤其自主执行模式意味着信任模型和目标账号权限。生产应配合 OS 权限、Kubernetes RBAC 与网络隔离，不要仅依靠模型提示词。
- 高风险删除、主机破坏命令、特权 Pod 配置仍需审批。停止任务不等于事务回滚：已经发往远端的操作或派生进程可能继续运行，需要检查远端实际状态。
- 允许用户配置内网供应商和服务器是平台的核心能力，因此此应用具有主动访问内网的权限。仅向可信运维人员开放注册和访问。初始账号创建后可关闭 `EARTHAI_ALLOW_REGISTRATION`。

## 运行和恢复说明

任务不依赖浏览器连接。页面切换、SSE 短暂中断不影响执行；刷新后从数据库恢复事件。

后端进程重启时，未完成任务会标记 `interrupted`，不会冒险自动重放可能有副作用的命令；用户应核查执行记录并重新发起目标。持久化记录不等于分布式 durable workflow 引擎。

调度器以 5 秒为粒度检查 cron，到期后创建一个真实 Agent 对话。执行会消耗所配置供应商的 API 配额。请谨慎设置高频任务，审批型定时任务也会等待人工审批。

文件单个最大 20 MB，PDF 最多 400 页，提取文本最多 200 万字符。扫描 PDF 不做 OCR。技能是给模型的操作方法，不是任意用户代码插件。告警目前为平台内告警和手动录入，未预置 Prometheus Alertmanager / PagerDuty / 钉钉集成。当前没有企业 SSO、配额计费和高可用集群；本轮团队角色仅治理团队空间与共享文件，不是全平台企业 RBAC。

## 备份与源码打包

备份需在**同时具备源码和 NAS 访问权限的维护环境**执行；不能假定 Docker 宿主机有 NAS 路径。当前镜像不包含 `scripts/backup.py`，不要假定可在应用容器内直接调用该脚本。先暂停任务、上传并停止全部写入者，再用 Python 标准库运行源码中的 `python3 scripts/backup.py`：将 `EARTHAI_DATA_DIR` 指向该维护容器或平台环境实际可见的 NAS 数据根目录，清除旧 STATE/UPLOADS 覆盖，将 `EARTHAI_BACKUP_DIR` 设为同一 NAS 根目录下的 `backups/`。只有维护环境确实可见该挂载时，才可使用其 `/app/data` 路径；不需另加应用挂载。完整步骤见 [NAS 更新说明](docs/USAGE-NAS-UPDATE.md)。

脚本通过 SQLite backup API 生成一致数据库快照并收集上传、品牌及磁盘主钥，归档权限 0600；文件与数据库的一致性仍依赖停写窗口。环境主钥不归档，须另外安全保管原值。也可在停写后使用 NAS 自身快照。同 NAS 的 `backups/` 或快照可防部分误操作，但 NAS 整体损坏仍可能一起丢失；NAS 自身 offsite 由用户策略安排，不要求新增应用挂载。

运行 `python3 scripts/package.py` 可生成不含虚拟环境、账号数据、上传文件、主密钥和测试数据的 `EarthAI-source.zip`，包含前端已构建产物。

## 目录

- `backend/main.py`：身份、管理 API、文件/知识库、SSE 与前端托管。
- `backend/engine.py`：多步工具调用引擎、审批、取消、cron 调度与重启恢复。
- `backend/tools.py`：SSH / Kubernetes / 文件 / 知识检索工具和风险策略。
- `backend/model_client.py`：真实模型 SSE / JSON 兼容解析、安全响应诊断与受限恢复。
- `backend/reliability.py`：工具schema校验、结果压缩、无进展限制与已验证协议记忆。
- `backend/text_tools.py`：原生网关不可靠时的显式JSON控制协议，执行仍走同一审批。
- `backend/progress.py`：公开回复和工具输出的增量事件与跨片段脱敏。
- `backend/store.py`：SQLite、FTS5、会话、安全哈希、加密和持久化事件。
- `backend/usage.py`：本地按任务/资源去重、远程独立点击事件、单资源/模板副本/全资源历史统计。
- `backend/storage_paths.py`：数据路径解析，旧 split API 仅为兼容；本次唯一 NAS 根目录直读写。
- `frontend/`：完整 React 应用。
- `tests/`：自动化测试。
- `deploy/`：Nginx、systemd 和 Kubernetes 最小只读 RBAC 示例。
